# What's New in DrogonSec v0.4.0: Full-depth SCA

**Released September 28, 2026** · [Release notes](https://github.com/filipi86/drogonsec/releases/tag/v0.4.0) · [CHANGELOG](https://github.com/filipi86/drogonsec/blob/main/CHANGELOG.md#040---2026-09-28)

DrogonSec's dependency engine now reads the tree that actually ships: every
transitive package, at the version installed. Before, it read only the handful
of packages a manifest declares. Vulnerabilities overwhelmingly live in the
packages nobody named, and v0.4.0 now covers them for all eight supported
ecosystems.

## Highlights

- **Every ecosystem in full.** npm, Yarn, Python, PHP, Rust (new) and Ruby are
  read from lockfiles and installed trees. Go and Dart are read from the package
  manager's own cache.
- **Java resolved offline.** Maven has no lockfile, so DrogonSec computes the
  dependency tree itself, by Maven's own rules. It matched `mvn dependency:tree`
  artifact for artifact on a Spring Boot application (102 artifacts) and a
  Hadoop / AWS SDK / netty one (130). `gradle.lockfile` is supported too.
- **Dependency paths.** Every SCA finding says how the vulnerable package got
  into the project, so the fix lands on the dependency a developer can actually
  change:

  ```
  #1 [CRITICAL] org.apache.logging.log4j:log4j-core 2.14.1
    CVE      : CVE-2021-44228  CVSS: 10.0
    Required : via com.example:core
    Fixed in : 2.17.1
  ```

- **SBOM dependency graph.** The CycloneDX 1.5 export carries every edge, ready
  for Grype, Trivy and Dependency-Track.
- **Stable fingerprints.** Every finding keeps its identity across scans and
  code moves, in JSON and as SARIF `partialFingerprints`, so GitHub Code
  Scanning no longer reopens an alert just because a line moved.

## Important fixes

- **Maven dependencies were never matched against an advisory.** They were
  named by `artifactId` alone, while OSV names them `groupId:artifactId`.
- **No more false positives from version ranges.** A manifest range such as
  `^4.17.15` is no longer matched against advisories as if it were a version.
  Projects scanned from manifests alone may see fewer SCA findings; committing a
  lockfile covers them in full.
- **Go:** versions are matched in OSV's format, and modules marked
  `// indirect` are no longer reported as direct.
- **Output:** `--severity` now applies to leak findings, and the banner and
  progress output go to stderr, so JSON, SARIF and SBOM output can be piped
  safely.

## Dependency Coverage

| Ecosystem | Read from | Depth |
|---|---|---|
| **Node.js** | `package-lock.json`, `yarn.lock`, `node_modules/`, `package.json` | Full tree |
| **Python** | `poetry.lock`, `uv.lock`, `Pipfile.lock`, `.venv/`, `pyproject.toml`, `requirements.txt` | Full tree |
| **Java** | `pom.xml` resolved offline against `~/.m2/repository`, `gradle.lockfile` | Full tree |
| **Go** | `go.mod` (Go 1.17+), routes from the module cache | Full set |
| **PHP** | `composer.lock`, `vendor/composer/installed.json`, `composer.json` | Full tree |
| **Rust** | `Cargo.lock`, `Cargo.toml` | Full tree |
| **Ruby** | `Gemfile.lock` | Full tree |
| **Dart** | `pubspec.lock`, `pubspec.yaml` | Full tree |

**No network needed.** DrogonSec never resolves dependencies against a
registry. It reads what the package manager has already recorded: the lockfile,
the installed tree, or the manifests kept in its cache (the Go module cache, the
pub cache, the Maven local repository or Gradle's cache). Scans therefore stay
reproducible and work in air-gapped environments. Only the advisory lookup
against OSV goes over the network.

**Where the cache is missing,** every package is still reported and direct
dependencies are still marked; only the routes are lost. For Maven, the scan
says how many POMs it could not find, and a single `mvn dependency:resolve`
fixes that.

How each ecosystem is read, rule by rule, is in the
[SCA engine documentation](../modules.md#sca-engine--software-composition-analysis).

## Get v0.4.0

```bash
# Go
go install github.com/filipi86/drogonsec/cmd/drogonsec@v0.4.0

# Docker
docker run --rm -v $(pwd):/scan ghcr.io/filipi86/drogonsec scan /scan

# Scan and export an SBOM with the dependency graph
drogonsec scan . --format cyclonedx --output sbom.json
```

Pre-built binaries for Linux, macOS and Windows (amd64 and arm64) are available
on the [release page](https://github.com/filipi86/drogonsec/releases/tag/v0.4.0).
